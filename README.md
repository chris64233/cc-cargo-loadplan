# cc-cargo-loadplan

航班货舱与货物单元管理服务：在重量、舱位和位置（重心）限制下生成并确认航班货物配载方案，并支持航班起飞前对已确认配载做**临时卸货 + 替换货物**的版本化调整。

## 开发环境

- JDK 21
- Maven Wrapper 3.9.9
- Spring Boot 4.1.1

迁移项目沿用现有 Spring Boot 版本，其他项目使用上述版本。

## 常用命令

运行测试：

    ./mvnw clean test

启动服务：

    ./mvnw spring-boot:run

## 领域模型

- **航班（Flight）**：空机重量/力臂、整机重心允许区间 `[minCg, maxCg]`、配置版本号、状态（OPEN/CLOSED）。
- **货舱（CargoHold）**：最大重量、最大体积、舱位力臂、允许装载的货物类别（空集合表示不限制）。
- **货物单元（CargoUnit）**：重量、体积、类别、不可同舱的类别集合、乐观锁版本；状态 AVAILABLE / LOCKED / UNLOADED。
- **配载方案（LoadPlan）**：方案号（全局唯一，幂等键）、状态 DRAFT / CONFIRMED / CANCELLED、指向当前生效版本（currentVersion）。
- **配载版本（PlanVersion）**：方案的一次完整装机快照，版本号在方案内单调递增；状态 DRAFT / CONFIRMED / SUPERSEDED / CANCELLED；携带航班配置版本快照、创建时间、变更号 changeNo 与该版本完整的货物→货舱安排（含货物版本快照）。**所有版本明细都保留。**
- **实际卸载事件（UnloadEvent）**：航班关闭后记录的实际卸载事实。

## 主要业务规则

1. **一个货物单元最多属于一个活动（已确认）配载方案。** 准备中的草案不锁定货物，确认时才原子锁定；货物被锁定后不能被其他方案确认，也不能修改重量。

2. **确认是原子的。** 确认时在单个事务内完成全部校验并锁定/切换全部货物单元：
   - 各货舱重量/体积上限、允许货物类别；
   - 互斥货物不可同舱（任一单元的不可同舱类别包含对方类别即冲突，双向判定）；
   - 整机重心区间：重心 = (空机重量 × 空机力臂 + Σ 货物重量 × 舱位力臂) / 总重量，必须落在 `[minCg, maxCg]` 内。

   任一约束不满足即整体回滚，不会留下部分装载状态。准备方案/准备调整时也会做同样的完整预检。

3. **方案号幂等。** 重复创建同一方案号返回既有方案；重复确认已确认版本直接返回。并发场景下由航班行悲观写锁串行化确认/调整操作，配合货物乐观锁与方案号唯一约束：多个方案争抢同一货物或剩余舱位时最多一个成功，其余收到 409/422。

4. **快照失效。** 准备时记录航班配置版本与每个货物的版本快照。确认前任一货物被修改（货物版本递增）或航班配置变更（重心区间/货舱限制，配置版本递增），快照比对失败返回 409，必须重新准备。

5. **起飞前临时卸货与替换货物（版本化调整，核心能力）。** 对已确认方案，先调用调整接口生成一个新的 **DRAFT 版本**，再调用确认接口使其生效：
   - **调整形成新版本，按整份方案重新核算。** 新版本保存调整后整份装机方案的完整安排（在机维持原舱的货物、重新分舱的货物、卸下的货物、新加入的替换货物），并据此整机重新计算货舱占用、重量、体积、重心与同舱限制；准备阶段不改动任何实际占用，原已确认版本继续有效。约束不满足（422）时不产生新版本，原配载不变。
   - **确认时同一事务切换全部货物与舱位。** 新加入（替换）货物锁定到目标舱、在机货物改舱、卸下货物释放回 AVAILABLE，三者在同一事务内一次性提交。确认前会再次校验替换货物仍可用；**替换货物不可用（已被其他方案占用）或快照失效时整体回滚，原已确认配载继续有效。**
   - **并发只允许一个结果。** 航班关闭（起飞）、替换货物被其他方案占用与调整确认并发时，由航班行悲观写锁串行化、以航班配置版本与货物乐观版本双重把关：旧快照的调整不能确认，同一替换货物只会被一个方案锁定，其余收到 409 且原配载不受影响。
   - **卸下只释放一次、请求幂等、版本明细保留。** 每次调整用变更号 `changeNo` 标识；同一方案重复提交相同 changeNo 返回既有版本（不重复卸货/占用），重复确认已确认版本直接返回。确认成功后旧版本变为 SUPERSEDED、新版本为 CONFIRMED，可经版本接口逐版追溯每一版的完整安排以及相对上一版卸下/加入的货物。同一方案至多保留一个待确认草案，以新 changeNo 提交会使旧草案作废（CANCELLED）。
   - 也支持**整组卸载**（不保留配载）：释放方案全部货物并把方案、当前版本及待确认草案置为 CANCELLED；该操作幂等，货物只释放一次。

6. **航班关闭后方案不可修改。** 关闭（起飞）后确认/调整/卸载方案均返回 409，调整草案也无法确认（卸下不会发生）；只能记录实际卸载事件（UnloadEvent），已卸载货物状态变为 UNLOADED，保留航班/舱位/方案信息供去向追溯。

## 配载版本生命周期

```
准备初版 createPlan            准备调整 adjust(changeNo)            再调整
   │ DRAFT v1          ┌──────────────────────────────┐
   ▼                    │                              ▼
 confirm            v1 CONFIRMED ──confirm──▶ v2 CONFIRMED ──confirm──▶ v3 CONFIRMED
   │                    │  (v1 SUPERSEDED)            (v1/v2 SUPERSEDED)
   ▼                    └─ 确认失败/409/422：v1 继续有效，草案可作废后重准备
 v1 CONFIRMED
   │ 整组卸载 unload
   ▼
 CANCELLED（货物全部释放，版本明细保留）
```

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/flights` | 创建航班（含货舱定义） |
| GET | `/api/flights/{flightNo}` | 航班详情 |
| PUT | `/api/flights/{flightNo}/config` | 变更航班配置（使准备中的版本快照失效） |
| POST | `/api/flights/{flightNo}/close` | 关闭航班（起飞） |
| GET | `/api/flights/{flightNo}/hold-usage` | 舱位用量查询 |
| GET | `/api/flights/{flightNo}/constraints` | 约束计算（整机重心与违规明细） |
| POST | `/api/flights/{flightNo}/unload-events` | 记录实际卸载事件（仅关闭后） |
| POST | `/api/cargo-units` | 登记货物单元 |
| PUT | `/api/cargo-units/{unitNo}/weight` | 修改货物重量（仅空闲货物） |
| GET | `/api/cargo-units/{unitNo}/whereabouts` | 货物去向查询 |
| POST | `/api/flights/{flightNo}/plans` | 准备配载方案（方案号幂等），生成版本 1 草案 |
| GET | `/api/plans/{planNo}` | 方案查询（含当前版本号与全部版本概要） |
| POST | `/api/plans/{planNo}/adjust` | 起飞前临时卸货/替换：按 changeNo 幂等生成新 DRAFT 版本并整机重算 |
| GET | `/api/plans/{planNo}/versions` | 全部配载版本（按版本号升序，含历史/草案） |
| GET | `/api/plans/{planNo}/versions/{versionNo}` | 单个版本明细（完整安排、卸下/加入货物、快照） |
| POST | `/api/plans/{planNo}/confirm` | 确认当前待生效版本（无草案时确认初版），原子切换占用，幂等 |
| POST | `/api/plans/{planNo}/versions/{versionNo}/confirm` | 确认指定版本 |
| POST | `/api/plans/{planNo}/unload` | 整组卸载（仅关闭前，幂等） |

调整请求体示例（卸下 `U-OLD`，把在机货物 `U-2` 调到 FWD，并加入替换货物 `U-NEW`）：

```json
{
  "changeNo": "CHG-20260928-01",
  "assignments": [
    {"unitNo": "U-2",   "holdCode": "FWD"},
    {"unitNo": "U-NEW", "holdCode": "AFT"}
  ],
  "unloadUnitNos": ["U-OLD"]
}
```

错误码：404 资源不存在；409 业务冲突（快照失效、替换货物被占用、航班已关闭、版本已作废、并发冲突）；422 配载约束不满足（响应体 `violations` 含全部违规明细）。
