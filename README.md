# cc-cargo-loadplan

航班货舱与货物单元管理服务：在重量、舱位和位置（重心）限制下生成并确认航班货物配载方案。

## 开发环境

- JDK 21
- Maven Wrapper 3.9.9
- Spring Boot 4.1.1

迁移项目沿用现有 Spring Boot 版本，其他项目使用上述版本。

## 常用命令

运行测试：

    ./mvnw clean test

启动服务：

    ./mvnw spring-boot:run

## 领域模型

- **航班（Flight）**：空机重量/力臂、整机重心允许区间 `[minCg, maxCg]`、配置版本号、状态（OPEN/CLOSED）。
- **货舱（CargoHold）**：最大重量、最大体积、舱位力臂、允许装载的货物类别（空集合表示不限制）。
- **货物单元（CargoUnit）**：重量、体积、类别、不可同舱的类别集合、乐观锁版本；状态 AVAILABLE / LOCKED / UNLOADED。
- **配载方案（LoadPlan）**：方案号（全局唯一，幂等键）、状态 DRAFT / CONFIRMED / CANCELLED、航班配置版本快照、货物→货舱安排（含货物版本快照）。
- **配载版本（PlanVersion）**：方案的版本明细。首次确认形成版本 1（ACTIVE）；每次起飞前临时卸货/替换/重新分舱的调整都追加一个新版本。版本状态为 PROPOSED（待确认候选，不占货物/舱位）/ ACTIVE（当前生效）/ SUPERSEDED（被取代，明细永久保留）。版本内保存完整的货物→货舱安排及航班配置、货物版本快照。
- **实际卸载事件（UnloadEvent）**：航班关闭后记录的实际卸载事实。

## 主要业务规则

1. **一个货物单元最多属于一个活动（已确认）配载方案。** 准备中的草稿方案不锁定货物，确认时才原子锁定；货物被锁定后不能被其他方案确认，也不能修改重量。

2. **确认是原子的。** 确认时在单个事务内完成全部校验并锁定全部货物单元：
   - 各货舱重量/体积上限、允许货物类别；
   - 互斥货物不可同舱（任一单元的不可同舱类别包含对方类别即冲突，双向判定）；
   - 整机重心区间：重心 = (空机重量 × 空机力臂 + Σ 货物重量 × 舱位力臂) / 总重量，必须落在 `[minCg, maxCg]` 内。
   任一约束不满足即整体回滚，不会留下部分装载状态。准备方案时也会做同样的完整预检。

3. **方案号幂等。** 重复创建同一方案号返回既有方案；重复确认已确认方案、重复整组卸载均直接返回。并发场景下由航班行悲观写锁串行化确认/调整操作，配合货物乐观锁与方案号唯一约束：多个方案争抢同一货物或剩余舱位时最多一个成功，其余收到 409/422。

4. **快照失效。** 方案准备时记录航班配置版本与每个货物的版本快照。准备期间货物重量被修改（货物版本递增）或航班配置变更（重心区间/货舱限制，配置版本递增）后，旧方案确认时快照比对失败，返回 409，必须重新准备方案。

5. **航班关闭前可临时卸货、加入替换货物，调整形成新版本。** 调整分两步：
   - `POST /plans/{planNo}/adjust`：以当前生效版本为基线，应用"临时卸货（unloadUnitNos）+ 重新分舱/加入替换货物（assignments）"生成一个 **PROPOSED 新版本**，并对调整后的**整份方案**重新校验各货舱重量/体积、允许类别、互斥同舱与整机重心；任一不满足返回 422，不生成新版本，原配载不变。此步不改动任何货物状态与舱位占用。
   - `POST /plans/{planNo}/adjust/confirm`：确认时在**单个事务**内完成航班/货物版本快照比对、替换货物可用性检查与整份方案约束复核，随后一次性切换：被卸货物释放（每件只释放一次）、保留货物移动到新舱位、替换货物锁定入舱，原版本置为 SUPERSEDED、新版本置为 ACTIVE。任一环节失败即整体回滚——**替换货物不可用（被其他方案占用）、快照失效、航班已关闭时，原配载继续有效**。
   - 未确认的候选版本会被再次 adjust 重新生成（不累积版本号）；确认后历史版本明细全部保留，可通过方案查询回溯每个版本的装机安排。
   - 整组卸载（`/unload`）释放当前版本全部货物并取消方案，各版本明细同样保留；重复调用幂等，不二次释放。

6. **并发只允许一个结果。** 航班起飞（关闭）、货物被其他方案占用、多个调整确认并发时：同一航班的变更由航班行悲观写锁串行化，跨航班争抢同一货物由货物乐观锁版本兜底，配合确认时的快照比对——最多一个事务提交成功，其余收到 409 且原配载不受影响。

7. **航班关闭后方案不可修改。** 关闭后确认/调整/确认调整/卸载方案均返回 409，只能记录实际卸载事件（UnloadEvent）；已卸载货物状态变为 UNLOADED，保留航班/舱位/方案信息供去向追溯。

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/flights` | 创建航班（含货舱定义） |
| GET | `/api/flights/{flightNo}` | 航班详情 |
| PUT | `/api/flights/{flightNo}/config` | 变更航班配置（使准备中的方案快照失效） |
| POST | `/api/flights/{flightNo}/close` | 关闭航班 |
| GET | `/api/flights/{flightNo}/hold-usage` | 舱位用量查询 |
| GET | `/api/flights/{flightNo}/constraints` | 约束计算（整机重心与违规明细） |
| POST | `/api/flights/{flightNo}/unload-events` | 记录实际卸载事件（仅关闭后） |
| POST | `/api/cargo-units` | 登记货物单元 |
| PUT | `/api/cargo-units/{unitNo}/weight` | 修改货物重量（仅空闲货物） |
| GET | `/api/cargo-units/{unitNo}/whereabouts` | 货物去向查询 |
| POST | `/api/flights/{flightNo}/plans` | 准备配载方案（方案号幂等） |
| GET | `/api/plans/{planNo}` | 方案查询 |
| POST | `/api/plans/{planNo}/confirm` | 确认方案（原子锁定，形成版本 1，幂等） |
| POST | `/api/plans/{planNo}/adjust` | 准备临时卸货/替换调整：整份方案重新校验并生成 PROPOSED 新版本（不改变占用） |
| POST | `/api/plans/{planNo}/adjust/confirm` | 确认调整：同事务切换全部货物与舱位占用，新版本生效，失败则原配载继续有效 |
| POST | `/api/plans/{planNo}/unload` | 整组卸载（仅关闭前，幂等；版本明细保留） |

错误码：404 资源不存在；409 业务冲突（快照失效、货物被占用、航班已关闭、并发冲突）；422 配载约束不满足（响应体 `violations` 含全部违规明细）。
